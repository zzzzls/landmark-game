# 北京地标盲猜 UI 设计

这是本项目的设计入口。先读项目根目录 `AGENTS.md`、`PRODUCT.md`、`DESIGN.md` 及目标组件，确认任务范围与实际实现。已有视觉身份是像素北京街机；“更精致”“参考这些网站”不意味着换成玻璃、柔和圆角或通用 SaaS 风格。

## 将参考转成项目设计

1. 看当前页面与代码，定位具体问题，如主操作与辅助信息抢注意力、边框层次过多、短屏地图被遮住。页面无法运行时注明证据限制。
2. 选与问题直接相关的真实参考，读取具体页面或本地示例。简要交代“来源 → 借鉴点 → 本项目位置”，不要把仅看过首页说成验证过组件。
3. 沿用已有 token 和共享组件，优先通过字号层级、留白、基线、密度、描边与硬阴影轻重改善界面。选定的新组件先检查 React 18、Vite、JSX 和 CSS 兼容性。
4. 完成请求范围内的实现和相称验证。按实际变化同步设计记录，不将计划或静态截图写成已完成的真实地图验收。

## 项目适配规则

- 保留浅天空蓝、奶白、海军蓝、金黄和薄荷绿的语义，本地原创像素 SVG、直角轮廓及数字字体。可微调层次与尺寸，不自动换字体、图标库、圆角体系或删除语义色。中文正文保持可读。
- 上游的“不要手绘 SVG”“统一替换字体”“只用一种强调色”“增加图片背景”等是通用建议，不覆盖本项目身份。禁止为了看起来真实而编造人数、分数、排名或业务文案。
- 出题/答题采用全幅地图与顶部悬浮搜索/题签，确认和取消使用落点旁 ✅/❌；管理与旁观仍使用底板/侧栏。按实际浮层尺寸避让；当前题、确认位置和主操作保持可见。保留真实地图、版权标识和四个公共 emoji 参照点。
- 服务端 state/匹配 ack 才表示成功；断线不能显示提交成功。成绩首帧就是服务端真实值，禁止从零累加、滚动数字、先模糊再显现或延迟揭示；未提交者不出现零分或庆祝。
- 动效用于说明变化，短暂且不阻塞。结算只在首次展示时播放，不因刷新或切页签重播；不循环装饰，不做磁吸主按钮、地图上的光效或妨碍连续落针的动画。必须支持 `prefers-reduced-motion`。
- 像素风保留清晰边缘；参考中的玻璃、柔焦、模糊数字、圆形高光和大幅弹跳不直接移植。悬停效果不能承担手机上唯一的反馈。

## 资源与依赖

- 项目允许引入 Tailwind，但在实际需要时才安装；先核实版本与当前 Vite 的兼容性，通过 npm 和本地构建集成，禁止 Tailwind Play CDN。避免全局 reset 无意覆盖地图、像素组件与 dialog。
- Motion、组件原语或其他依赖同样通过 npm 安装并纳入锁文件；按完整依赖关系适配，不能只复制 JSX 后留下一堆缺失的 helper。保持当前 React/Vite 架构，不为示例自动迁移 Next.js 或升级 React。
- 采用的字体、图片、图标、音频、视频、CSS、JS、worker/WASM 等全部保存到本项目并通过 Vite import 或同源静态路径提供。字体需自托管；CSS 的嵌套 `@import`/`url()`、SVG 外链和脚本动态资源也须检查。外部占位图不得留到运行时。
- 下载实际采用且允许使用的资源，保留来源与必要许可证；不批量镜像参考网站、不抓取付费组件。公开文档链接可以保留为开发资料，不能成为 UI 资源依赖。
- 运行时允许本机/局域网同源 API、WebSocket，以及真实高德地图必要的 SDK、地图资源、瓦片和地点搜索请求；其余第三方资源必须本地化。开发期可以联网查文档和下载依赖。

## 验证

检查受影响的玩家 `/`、管理员 `/admin`、大屏 `/screen`，覆盖 360/390/430 手机与桌面/大屏中相关尺寸，以及短屏、长名称、软键盘、焦点、减少动态效果。地图或状态流程改变时运行真实地图 UI 流程，不用静态截图替代。

资源检查使用独立、初始无房间的后端与生产构建预览，运行根目录 `npm run test:resources`，具体启动方式见 `PLAYTEST.md`。记录域名、资源类型与通过/失败状态；不输出完整地图 URL、查询串、密钥，不保存 trace/HAR。区分“没有不允许的外部请求”和“地图实际加载成功”，两项都满足才通过资源验收。
